## 一、反例测试（针对 3 项缺口，共 5 组）

| # | 反例场景 | 测试函数 | 期望 | 结果 |
|---|---|---|---|---|
| 1 | 弱口令（常见词 `admin123`、纯数字 `12345678`、纯字母 `abcdefgh`、过短 `Ab1!`、低多样性 `aaaa1111`）经 `init-admin` 创建管理员 | `test_init_admin_rejects_weak_passwords` | 全部 **400** 且**不落库** | ✅ PASS |
| 2 | 强口令经 `init-admin` 正常创建管理员 | `test_init_admin_accepts_strong_password` | **200** 且 `count==1` | ✅ PASS |
| 3 | 10 线程并发冷启动引导（同一用户名 + 强口令） | `test_create_first_admin_concurrent_atomic` | 无 **500** 异常，最终仅 **1** 个管理员 | ✅ PASS |
| 4 | 模拟"执行成功 → 记账 `success` 前崩溃"：仅占坑 `pending`，重放应安全重执行并补记 `success` | `test_executor_crash_window_replay_is_safe` | 重放执行成功、最终仅 **1** 条 success、再次进入命中幂等 | ✅ PASS |
| 5 | 升级前无 `status` 列的老 `ledger.db` 应自动迁移并可用 | `test_ledger_migration_from_legacy_schema` | 迁移后 `claim_pending`/`update_status`/`get` 正常 | ✅ PASS |

> 既有回归测试 `test_executor_idempotent_no_duplicate_side_effect`（同 key 重放不重复副作用）继续覆盖幂等基本语义，不重复计数。

## 二、回归风险清单

| 风险点 | 影响范围 | 处置 |
|---|---|---|
| 弱口令校验 | 所有经 `create_user` 的账号创建路径（`init-admin`、未来注册）被强制拦截；**不影响**登录校验、**不影响** dev 演示种子（走 `_seed` 原始 INSERT） | 已在路由层把 `CredentialError` 转 400；dev 演示账号不受影响 |
| 并发原子函数 | `init-admin` 冷启动分支行为变化：竞速落败时会多记一条 `ADMIN_BOOTSTRAP`（detail `via=init-admin-race-lost`） | 审计语义清晰，无副作用；单用户正常创建路径行为不变 |
| 幂等台账 schema 变更 | `execution_ledger` 新增 `status` 列；**已存在的老 `ledger.db`** 升级后旧 INSERT/UPDATE 会因缺列失败 | `_c()` 内置 `PRAGMA table_info` 检测 + `ALTER TABLE ADD COLUMN`（反例 #5 覆盖） |
| `executor_node` 判定字段 | 命中由 `result=='success'` 改为 `status=='success'` | 与 `claim_pending`/`update_status` 配套；既有 `test_executor_idempotent` 仍通过 |
| 既有测试数据 | `test_init_admin_bootstrap_then_locked` 的 r3 原用纯字母 `y*24`，被新策略正确拒绝 | 已改为强口令 `YyStr0ng!Admin2`，测试恢复通过 |

## 三、缺口逐条打勾

| 缺口 | 是否关闭 | 证据 |
|---|---|---|
| ① 弱口令治理（`admin/admin123` 仍能经 `init-admin` 进入生产） | ✅ 关闭 | `security.validate_password_strength` + `create_user`/`create_first_admin_if_absent` 强制校验；反例 #1/#2 |
