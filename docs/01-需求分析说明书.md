## 0. 文档目的与范围

本说明书在**教学演示版**基础上进行企业级重构的需求梳理，明确平台"做什么、为什么做、做到什么程度"。

教学版（教材原版）定位为"能跑通 LangGraph 机制的最小示例"，存在以下**生产级缺口**，本企业版需求即围绕这些缺口展开：

| 维度 | 教学版现状 | 企业级需求 |
|------|-----------|-----------|
| 知识引擎 | 关键词匹配，非真实 RAG | 向量化 RAG，可离线运行，可切换大模型 |
| 状态持久化 | `MemorySaver` 内存存储，重启即丢 | 持久化 Checkpointer（SQLite/Postgres），支持跨天/重启恢复 |
| 审计能力 | 无 | 独立审计子系统，全链路留痕、可溯源、可导出 |
| 认证授权 | 无，任何人可调接口 | JWT 鉴权 + RBAC 角色（申请人/审批人/管理员） |
| 架构 | 单文件拼装 | 分层架构（config/core/schemas/services/workflows/api） |
| 可观测性 | `print` 输出 | 结构化日志、健康检查、指标、执行追踪 |
| 部署 | `python main.py` | 容器化（Docker）、环境变量配置、可水平扩展 |
| 测试 | 无 | 单元/集成测试 + 验收用例 |

## 1. 项目背景

企业采购、报销、合同等审批业务存在以下痛点：

1. **人工初审耗时长**：标准化申请（如常规采购）仍需人工判断风险等级，平均耗时 48 小时。
2. **规则随制度频繁变化**：企业制度更新需改代码、重新部署，维护成本高。
3. **流程不可恢复**：审批人可能跨天、跨周处理，服务重启后流程易丢失。
4. **无据可查**：AI 决策"凭感觉"，无法溯源依据，难满足合规审计要求。

**目标**：构建一套基于 LangGraph 多智能体协作的智能工作流平台，用 AI 风险评估替代人工初审，用 RAG 让决策有据可依，用 Human-in-the-Loop 保留人工决策权，用图级别循环重试保障执行可靠性，并配套完整审计能力。

## 2. 业务场景与范围

### 2.1 统一业务场景：企业采购审批工作流

```
员工提交采购申请 → AI 自动风险分析(RAG) → 低风险自动放行 / 高风险转人工审批
→ 审批通过后自动执行 → 失败自动重试 → 生成报告 → 全程审计留痕
```

### 2.2 本期范围（MVP）

- 采购审批（procurement）场景完整闭环
- 费用报销（expense）、请假（leave）场景复用同一套 Agent 架构（数据模型与路由已支持）

### 2.3 不在本期范围

- 真实供应商 API 对接（以适配器接口预留，模拟执行）
- 多级动态审批链（经理→总监→VP→CFO 自动生成）—— 列为进阶扩展
- 钉钉/飞书/邮件 Webhook 通知 —— 列为进阶扩展

## 3. 用户角色（Stakeholders）

| 角色 | 标识 | 职责 | 权限 |
|------|------|------|------|
| 申请人 | `applicant` | 提交申请、查看自己申请的状态与报告 | 提交、查询本人 |
| 审批人 | `approver` | 查看待审批列表、批准/驳回、填写意见 | 待办审批、查询 |
| 管理员 | `admin` | 知识库管理、审计日志查看、系统配置、指标监控 | 全部 |
| 系统/服务 | `system` | 工作流引擎自动执行节点 | 内部调用 |

## 4. 功能需求（Functional Requirements）

### 4.1 多 Agent 协作编排（FR-01）
- **FR-01-1**：平台将审批流程拆分为 `Analyst`（风险分析）、`Approval`（人工审批）、`Executor`（自动执行）、`Monitor`（结束汇总）四个专职节点。
- **FR-01-2**：共享 `WorkflowState` 在节点间流转，日志字段（`logs`）使用 Reducer 累加而非覆盖。
- **FR-01-3**：低风险申请跳过审批节点直接进入执行；高风险进入审批节点。

### 4.2 RAG 知识引擎（FR-02）
- **FR-02-1**：企业规章制度文档可加载、分块、向量化入库。
- **FR-02-2**：分析节点执行前先检索 Top-K 相关规则并注入 Prompt/上下文。
- **FR-02-3**：支持**离线本地 Embedding**（无需外部 API 即可运行），同时支持切换 Sentence-Transformers / OpenAI / 通义千问 Embedding。
- **FR-02-4**：规则更新只需更新知识库文档，无需改代码。

### 4.3 Human-in-the-Loop 审批（FR-03）
- **FR-03-1**：高风险/需审批申请在 Executor 节点前自动暂停（`interrupt_before`）。
- **FR-03-2**：审批人通过接口/界面提交"通过/驳回"及意见，系统恢复工作流继续执行。
- **FR-03-3**：支持跨天审批与服务重启后恢复（持久化 Checkpointer）。
- **FR-03-4**：审批超时（>24h）自动提醒，>72h 自动上报（进阶，接口预留）。

### 4.4 图级别循环重试（FR-04）
- **FR-04-1**：Executor 执行失败通过条件边形成图循环，自动重试最多 N 次（默认 3）。
- **FR-04-2**：每次重试生成完整状态快照（Checkpoint），可回放。
- **FR-04-3**：超过最大重试次数后优雅降级，生成失败报告。

### 4.5 审计子系统（FR-05）— 核心合规能力
- **FR-05-1**：记录每次工作流事件：节点进入/退出、状态变更、审批操作（含操作人、意见）、LLM 调用（含 token/耗时）、外部执行结果、异常。
- **FR-05-2**：审计记录不可篡改（写后即 append-only，含时间戳与操作主体）。
- **FR-05-3**：管理员可按 thread_id / 时间 / 操作人 / 事件类型查询与导出审计日志。

### 4.6 认证与授权（FR-06）
- **FR-06-1**：所有写接口需 JWT 鉴权。
- **FR-06-2**：审批接口仅 `approver`/`admin` 可调用；提交接口申请人可用；审计查询仅 `admin`。

### 4.7 监控与可观测（FR-07）
- **FR-07-1**：结构化日志（JSON）输出到文件/标准输出。
- **FR-07-2**：提供 `/health` 健康检查、`/metrics` 基础指标（总数/成功/待审/失败）。
- **FR-07-3**：前端看板实时展示工作流状态、节点进度、执行日志。

### 4.8 前端审批看板（FR-08）
- **FR-08-1**：提交申请表单（类型/详情/金额/部门）。
- **FR-08-2**：实时状态展示、风险等级、审批状态、重试次数。
- **FR-08-3**：人工审批交互（批准/驳回 + 意见）。
- **FR-08-4**：LangGraph 节点可视化、执行日志、报告展示、审计查询入口。

## 5. 非功能需求（Non-Functional Requirements）

| 类别 | 需求 | 指标 |
|------|------|------|
| 可用性 | 支持跨天审批、服务重启不丢流程 | 恢复成功率 ≥ 99.9% |
| 性能 | 单次申请分析+路由耗时 | P95 < 3s（规则/本地模型）；LLM 模式随模型 |
| 安全 | 传输/存储/鉴权 | JWT 有效期可控、密码哈希、敏感字段脱敏 |
| 审计 | 全链路留痕、不可篡改、可导出 | 覆盖率 100%，导出支持 CSV/JSON |
| 可维护性 | 分层架构、依赖注入、可插拔 Provider | 单文件改动 ≤ 1 处即可换模型/向量库 |
| 可移植 | 容器化部署 | 提供 Dockerfile + docker-compose |
| 可观测 | 日志/健康/指标 | 提供标准端点 |

## 6. 关键约束

1. **可离线运行**：默认配置下（无外部 API Key）平台必须能完整跑通演示（本地 Embedding + 规则兜底分析）。
2. **可插拔**：LLM、Embedding、向量库、Checkpointer 均为接口化，业务代码不因替换而改动。
3. **合规优先**：审计为强制能力，不可被关闭。

---

## 7. 验收标准（Acceptance Criteria）

1. 提交低风险申请 → 自动执行成功 → 生成报告 → 审计记录完整。
2. 提交高风险申请 → 自动暂停 → 审批人批准 → 恢复执行 → 生成报告 → 审计含审批操作。
3. 模拟执行失败 → 自动重试至成功或超过上限 → 每次重试有快照与日志。
4. 提交后"重启服务"（新进程加载同一持久化库）→ 用 thread_id 仍可恢复并审批 → 状态不丢。
5. 未携带合法 JWT 调用审批接口 → 返回 401。
6. 管理员可查询任意 thread_id 的完整审计链并导出。
7. `pytest` 核心用例全部通过。

## 8. 风险与假设

| 风险 | 影响 | 缓解 |
|------|------|------|
| 外部 LLM 不可用/限流 | 分析降级 | 规则兜底 + 本地模型可选 |
| 向量库大数据量性能 | 检索变慢 | 分块优化 + 索引；FAISS 后端 |
| 审计数据膨胀 | 存储压力 | 按时间分区 + 归档策略 |
