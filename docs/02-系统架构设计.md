## 1. 架构总览

平台采用**分层 + 可插拔 Provider** 架构，纵向分接入层、应用层、领域层、基础设施层；横向贯穿审计、鉴权、可观测三条能力线。

```
┌──────────────────────────────────────────────────────────────────────┐
│                          接入层 (Access)                              │
│   前端审批看板(HTML/JS)   │   REST API(FastAPI)  │   Swagger/OpenAPI    │
└───────────────┬──────────────────────┬───────────────────────────────┘
                │  JWT 鉴权 / RBAC       │
┌───────────────▼──────────────────────▼───────────────────────────────┐
│                      应用层 (Application)                            │
│   routers: workflow / approval / audit / auth / health / metrics      │
└───────────────┬──────────────────────┬───────────────────────────────┘
                │                       │
┌───────────────▼──────────┐  ┌─────────▼──────────────────────────────┐
│   领域层 (Domain)         │  │        横切能力 (Cross-cutting)          │
│  WorkflowEngine(LangGraph)│  │  AuditService(审计)  AuthService(JWT)   │
│   Analyst/Approval/       │  │  Observability(日志/指标/追踪)          │
│   Executor/Monitor 节点   │  └────────────────────────────────────────┘
└───────────────┬──────────┘
                │
┌───────────────▼──────────────────────────────────────────────────────┐
│                    基础设施层 (Infrastructure)                        │
│  KnowledgeEngine(RAG)  │  Checkpointer(SQLite/PG)  │  AuditStore(DB)  │
│  EmbeddingProvider     │  VectorStore(FAISS/Numpy) │  Config/Secrets  │
└──────────────────────────────────────────────────────────────────────┘
```

## 2. 教学版 → 企业版：架构差异

| 项 | 教学版 | 企业版 |
|----|--------|--------|
| 代码组织 | `config.py`/`workflow.py`/`api.py`/`app.py` 平铺 | 分层包：`core/ services/ workflows/ api/ schemas/ models/` |
| 知识引擎 | `knowledge_engine.py` 关键词匹配 | `KnowledgeEngine` + 可插拔 `EmbeddingProvider` + `VectorStore`，默认离线运行 |
| 持久化 | `MemorySaver`（易失） | `SqliteSaver`/`PostgresSaver` 持久化 Checkpointer |
| 审计 | 无 | 独立 `AuditService` + `AuditStore`（append-only） |
| 认证 | 无 | `AuthService`（JWT + bcrypt + RBAC） |
| LLM | `ChatTongyi` 硬编码 | `LLMProvider` 接口：规则兜底 / OpenAI / 通义千问 |
| API | 同步 `def`，无鉴权 | 异步 `async def` + 依赖注入鉴权 + 统一响应/错误码 |
| 前端 | Streamlit 单体 | FastAPI 托管轻量 SPA（无构建步骤，开箱即用） |
| 部署 | `python main.py` | Dockerfile + docker-compose + 健康检查 |

## 3. 分层职责说明

### 3.1 `core/` — 基础设施与横切
- `config.py`：环境变量配置（Pydantic Settings），含密钥、阈值、模型名、DB 路径。
- `security.py`：JWT 签发/校验、密码哈希（bcrypt）、RBAC 依赖。
- `logging.py`：结构化 JSON 日志。
- `database.py`：审计库与业务库的连接管理（SQLAlchemy async）。

### 3.2 `services/` — 领域服务
- `knowledge_service.py`：文档加载、分块、向量化、检索（RAG）。
- `audit_service.py`：审计事件写入与查询（企业版核心新增）。
- `auth_service.py`：用户与角色管理。
- `workflow_service.py`：封装 LangGraph app 的调用、暂停/恢复、状态查询。

### 3.3 `workflows/` — 工作流编排（LangGraph）
- `state.py`：`WorkflowState` TypedDict + Reducer。
- `agents.py`：四个节点函数（analyst/approval/executor/monitor）。
- `graph.py`：`build_workflow()` 编译 StateGraph，配置持久化 Checkpointer 与 `interrupt_before`。
- `providers.py`：可插拔 `LLMProvider` / `EmbeddingProvider` / `VectorStore` 实现。

### 3.4 `api/` — 接口层
- `routers/`：`workflow.py`、`approval.py`、`audit.py`、`auth.py`、`system.py`（health/metrics）。
- `deps.py`：鉴权依赖注入。
- `main.py`：应用装配、CORS、静态前端托管、异常处理器。

### 3.5 `schemas/` — 数据契约
- Pydantic 请求/响应模型，与 OpenAPI 自动联动。

### 3.6 `models/` — ORM 模型
- `user.py`、`audit_log.py` 等 SQLAlchemy 模型。

## 4. 关键设计决策（ADR 摘要）

### ADR-1：可插拔 Provider，默认离线运行
- **背景**：沙箱/内网可能无外部 LLM/Embedding API。
- **决策**：定义 `LLMProvider`、`EmbeddingProvider`、`VectorStore` 抽象；默认实现为规则分析 + 本地字符 n-gram/Numpy 余弦向量，无需下载模型即可运行；配置指向 OpenAI/通义千问/Sentence-Transformers 时自动切换。
- **收益**：演示零依赖可用，生产可无缝升级；业务代码零改动。

### ADR-2：持久化 Checkpointer 替代 MemorySaver
- **背景**：教学版 `MemorySaver` 进程内易失，不支持跨天/重启恢复。
- **决策**：使用 `langgraph-checkpoint-sqlite` 的 `SqliteSaver`（文件持久化）作为默认；生产可用 `AsyncPostgresSaver`（仅改配置）。
- **收益**：满足 FR-03-3 跨天/重启恢复，且 Checkpointer 接口化，业务无感。

### ADR-3：独立审计子系统（append-only）
- **背景**：合规要求全链路留痕、不可篡改、可溯源。
- **决策**：`AuditService` 在每个关键节点/操作前后写入审计事件到独立审计库表；记录 `actor`(操作主体)、`action`、`thread_id`、`before/after` 摘要、`timestamp`、`trace_id`。
- **收益**：审计与业务解耦，可独立查询导出，满足 FR-05。

### ADR-4：异步 FastAPI + 依赖注入鉴权
- **背景**：需鉴权、可水平扩展、统一契约。
- **决策**：接口全部 `async def`；`Depends(get_current_user)` + 角色校验；统一 `ApiResponse` 与错误码。

## 5. 工作流状态机（LangGraph）

```
START ─▶ analyst ──route_after_analysis──▶ approval ──route_after_approval──▶ executor
              │                                  │                              │
              └──────────(低风险)────────────────┘              route_after_execution
                                                                    │
                                              ┌─────────成功/超限────────▶ monitor ─▶ END
                                              └─────────失败(<max)─────────▶ executor (循环重试)
```

- `interrupt_before=["executor"]`：高风险审批暂停点。
- `approval` 节点本身极简，仅登记"待审批"；真实审批由外部 `update_state` 注入。

## 6. 技术选型

| 能力 | 选型（默认/可选） | 说明 |
|------|------------------|------|
| 语言 | Python 3.11 | — |
| 工作流引擎 | LangGraph ≥ 0.2 | StateGraph + Checkpointer |
| Web 框架 | FastAPI + Uvicorn | 异步、OpenAPI |
| 校验 | Pydantic v2 | 数据契约 |
| 持久化检查点 | SqliteSaver / AsyncPostgresSaver | 状态恢复 |
| 关系/审计库 | SQLAlchemy async + SQLite/PG | 审计表、用户表 |
| 向量检索 | Numpy 余弦（默认）/ FAISS | RAG |
| Embedding | 本地 n-gram（默认）/ ST / OpenAI / 通义 | 可插拔 |
| LLM | 规则兜底（默认）/ OpenAI / 通义千问 | 可插拔 |
| 鉴权 | python-jose(JWT) + bcrypt | RBAC |
| 前端 | 原生 HTML/JS SPA（FastAPI 托管） | 无构建 |
| 容器 | Docker + docker-compose | 部署 |
| 测试 | pytest + httpx(AsyncClient) | 验证 |
