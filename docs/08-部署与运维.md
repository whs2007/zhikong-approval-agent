> 文档版本：v1.0
> 前置文档：《02-系统架构设计》《03-数据库与持久化设计》

---

## 1. 环境要求
- Python ≥ 3.11
- （可选）PostgreSQL ≥ 14（生产）
- Docker ≥ 24（容器化部署）

---

## 2. 本地运行（开发/演示）

```bash
cd zhikong
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# 可选：复制 .env.example 为 .env 并调整
uvicorn api.main:app --host 0.0.0.0 --port 8000 --reload
```
- 打开 `http://localhost:8000/` 使用审批看板。
- Swagger：`http://localhost:8000/docs`。
- 首个管理员：通过 `POST /api/v1/auth/init-admin` 创建（口令需满足强度策略）；
  演示环境可设 `DEMO_SEED=1` + `DEMO_*_PASSWORD`，但**生产环境禁止**（启动时会被拒绝）。

> 默认配置（无外部 API Key）即**离线可用**：本地 n-gram Embedding + 规则兜底分析 + SQLite 持久化。

## 3. 环境变量（`.env`）

| 变量 | 说明 | 默认 |
|------|------|------|
| `ENV` | dev/prod | dev |
| `SECRET_KEY` | JWT 签名密钥 | 随机生成（prod 必改） |
| `JWT_EXPIRE_MINUTES` | 令牌有效期 | 60 |
| `DB_URL` | 审计/业务库 | sqlite+aiosqlite:///data/db/zhikong.db |
| `CHECKPOINTER` | sqlite / postgres | sqlite |
| `CHECKPOINTER_DB` | sqlite 文件路径 | data/db/checkpoints.db |
| `POSTGRES_URL` | 生产 Checkpointer 连接串 | — |
| `EMBEDDING_PROVIDER` | local / st / openai / dashscope | local |
| `LLM_PROVIDER` | rule / openai / dashscope | rule |
| `OPENAI_API_KEY` / `DASHSCOPE_API_KEY` | 外部 LLM | — |
| `AUTO_APPROVE_THRESHOLD` | 自动审批阈值(元) | 5000 |
| `MAX_RETRY` | 最大重试次数 | 3 |

## 4. 容器化部署

### 4.1 Dockerfile（要点）
- 基于 `python:3.11-slim`
- 安装 `requirements.txt`
- 暴露 8000
- 启动命令：`uvicorn api.main:app --host 0.0.0.0 --port 8000`

### 4.2 docker-compose（要点）
```yaml
services:
  zhikong:
    build: .
    ports: ["8000:8000"]
    environment:
      - CHECKPOINTER=postgres
      - POSTGRES_URL=postgresql://${DB_USER}:${DB_PASSWORD}@db:5432/zhikong
      - DB_URL=postgresql+asyncpg://${DB_USER}:${DB_PASSWORD}@db:5432/zhikong
    volumes: ["./data:/app/data"]
    depends_on: [db]
  db:
    image: postgres:16
    environment:
      - POSTGRES_USER=zhikong
      - POSTGRES_PASSWORD=${DB_PASSWORD:?请注入数据库口令，切勿使用示例口令}
      - POSTGRES_DB=zhikong
    volumes: ["pgdata:/var/lib/postgresql/data"]
volumes: { pgdata: {} }
```
> 生产将 `CHECKPOINTER` 切 `postgres`，业务库与检查点均落 PG，满足高可用。

## 5. 运维要点
- **健康检查**：`GET /health`（探测 db 与 checkpointer）。
- **指标**：`GET /metrics`（总数/成功/待审/失败/平均耗时）。
- **日志**：结构化 JSON 输出，建议接入 ELK/Loki。
- **知识库更新**：放入 `data/knowledge/` 后调 `POST /knowledge/reload`。
- **审计留存**：按《03》§7 定期归档 `audit_log`。
- **备份**：SQLite 文件 / PG 实例定期备份；Checkpointer 与审计库同备份策略。

---

## 6. 升级路径（生产增强建议）
1. 反向代理（Nginx）终止 TLS + 限流。
2. Checkpointer 切 Postgres + 连接池。
3. 向量库切 FAISS/PGVector，支持大数据量。
4. LLM/Embedding 接入企业内网网关，启用 LangSmith 追踪。
5. 多级审批链、Webhook 通知（见教材进阶方向）。
